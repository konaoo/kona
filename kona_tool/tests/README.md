# kona_tool/tests 目录说明

`kona_tool/tests/` 放的是后端正式测试。

这里的文件不是临时验证脚本，而是应该能被反复执行、用于保护线上逻辑的测试。

---

## 1. 这里应该放什么

- 单元测试
- 接口测试
- 回归测试
- 价格源相关测试
- 快照 / 分析 / 收益口径测试
- 管理后台与认证流程测试

---

## 2. 这里不应该放什么

- 手工验证脚本
- 临时排障脚本
- 跑完一次就没价值的输出文件
- 和正式测试流程无关的试验代码

判断标准很简单：

如果一个文件不能稳定重复运行，或者它只是为了某次现场排障，那就不该留在这里。

---

## 3. 现在这组测试主要在保什么

当前测试大致分成几条主线：

- 后端基础接口
- 管理后台
- 登录与密码流程
- 资产代码识别
- 价格源优先级
- 价格缓存与容灾
- 快照 / 收益 / 分析口径
- 数据迁移与用户隔离
- 运维脚本

更详细的人话地图，直接看：

- [README_测试地图.md](/Users/kona/Desktop/kaka/kona_repo/kona_tool/tests/README_测试地图.md)

---

## 4. 当前建议

以后改后端逻辑时，不要只想着“跑一下全部测试”。

更合理的方式是：

1. 先判断你改的是哪条主线
2. 先跑对应主题测试
3. 再决定要不要补全量测试

这样效率更高，也更容易定位问题。
