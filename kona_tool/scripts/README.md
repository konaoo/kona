# kona_tool/scripts 目录说明

`kona_tool/scripts/` 放的是后端专属脚本，不是仓库级脚本。

这里适合放：

- 定时任务入口
- 数据修复脚本
- 运维辅助脚本
- 后端专属的一次性迁移脚本
- 本地开发库初始化脚本

这里不适合放：

- 纯临时排障脚本
- 跑完就没价值的输出文件

## 备份和日志保留

- `backup_portfolio_db.py`：每日数据库压缩备份成功后，维护项目上一级 `backups` 中已完成至少一小时的 `portfolio-before-*.db` 修复备份。逐个压缩、解压哈希校验后才移除原文件；只清理超过14天的自动基金对账备份，并至少留最新一份。人工修复备份只压缩、不按日期删除。路径和期限可用 `KONA_REPAIR_BACKUP_DIR`、`KONA_REPAIR_BACKUP_RETENTION_DAYS` 配置。
- `kona-system.logrotate`：腾讯云系统日志和快照日志的轮转配置，安装到 `/etc/logrotate.d/kona-system`。系统日志每日轮转、保留14份并压缩，超过100MB会在下一次轮转检查提前处理；业务任务日志阈值20MB。安装后先用 `logrotate -d /etc/logrotate.d/kona-system` 校验，首次可执行一次强制轮转；回退时移除该配置即可，已归档日志仍保留。
- 和后端主工程无关的试验文件

判断标准很简单：

如果脚本只服务 `kona_tool`，就放这里。
如果脚本服务整个仓库，应该放到仓库级 `scripts/`。

当前新增：

- `setup_local_demo_data.py`
  用途：重建本地固定测试账号 `konae / qq111111`，并补本地联调常用样例数据。
  范围：只动本地开发库，不碰线上。

- `reconcile_recent_fund_navs.py`
  用途：定时任务按 T+1 回扫最近 2 天场外基金的确认净值；手动排查时可回扫最近 7 天，只补缺失或与确认净值不一致的逐资产收益明细。
  默认检查缺失明细和未通过历史净值对账的零收益行（即使基数非零）；零收益只有来源为 `fund_nav_reconcile` 且基数有效时才跳过。没有目标日确认净值就提示待复核，不假设收益为零。带 `--apply` 才会写入补账结果，并在写入前生成 SQLite 一致性备份。`--verify-existing` 用于人工全面核验非零明细，不放进每天定时任务。场内基金、股票和当天数据不会处理；本次未扩大历史范围。注意：脚本导入数据库模块存在初始化动作，默认只检查不等于底层数据库强制只读，线上严格只读排查必须另用 `mode=ro` 查询。
