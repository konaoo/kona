# 资产收益计算逻辑

这份文档专门讲一件事：

`项目里“成本、当日盈亏、累计盈亏、快照、分析页”到底怎么算。`

这份文档尽量不用技术黑话，只回答你最常碰到的几个问题：

1. 成本价为什么有时不是你数据库里那一列？
2. `adjustment` 到底在干嘛？
3. 当日盈亏怎么算？
4. 累计盈亏怎么算？
5. 为什么投资页和分析页有时对不上？

---

## 1. 先说结论

项目里同时存在两套口径，但现在边界已经明确：

1. 实时口径  
   统一认后端 `/api/portfolio?with_metrics=1` 和 sync bootstrap 返回的持仓指标字段

2. 历史口径  
   统一认 `daily_snapshots` 和 `daily_snapshot_market_breakdowns` 里的历史快照

所以你修改了：

- 持仓成本
- `adjustment`
- 当前价格

会立刻影响实时页面；  
但不会自动改写过去每天已经落库的历史数据。

一句大白话：

`投资页 / 首页 / 实时汇总认“后端持仓指标”，分析页历史区间认“历史快照”。`

---

## 2. 成本价到底是什么

项目里其实有两种“成本”概念。

### 2.1 原始成本价

数据库持仓表里的：

- `price`

它表示这条持仓记录的原始成本单价。

比如：

- `price = 17.04`

这就是原始成本价。

### 2.2 摊薄后显示成本价

Flutter / Web 投资页里显示给你的“成本”不再由页面各自现算，统一认后端持仓指标里的：

- `display_cost_price`

对应产出位置：

- [portfolio_handlers.py](/Users/kona/Desktop/kaka/kona_repo/kona_tool/portfolio_handlers.py)

核心逻辑是：

```text
显示成本价 = ((原始成本价 × 持仓数量) - adjustment) / 持仓数量
```

也就是：

```text
displayCostPrice = ((rawCostPrice * qty) - adjustment) / qty
```

所以如果：

- `price = 17.04`
- `qty = 5867.59`
- `adjustment = 1000`

那页面上看到的成本价就不会是 `17.04`，而会变成更低的摊薄后成本。

这也是你之前看到 `16.8696` 的原因。

---

## 3. adjustment 是什么

`adjustment` 可以把它理解成：

`这条持仓已经发生过、但不再体现在当前持仓成本里的历史调整项。`

最常见的来源有：

- 卖出后已经实现的收益
- 分红
- 人工修正补差

从 `2026-03-20` 这轮开始，后端已经进入过渡期：

- `portfolio.adjustment` 只作为旧兼容字段保留
- 新发生的已实现盈亏，会写到 `portfolio_adjustment_ledger`
- 读侧实时口径会把两部分加总成一个总 adjustment 再参与累计盈亏计算

注意：

- 修改成本价
- 修改数量
- 修正录入错误

这类动作本质上是在改“当前持仓状态”，不应该再默认写进收益调整。

它的作用不是改“当前价格”，而是影响：

- 显示成本
- 累计盈亏

一句大白话：

`adjustment 会把历史已兑现的一部分收益，重新摊回这条持仓的收益表现里。`

所以它不是噪音字段，是收益口径的重要组成部分。

## 4. 单个持仓的累计盈亏怎么算

当前单个持仓的累计盈亏主口径，统一来自后端持仓指标：

- `total_pnl`
- `total_pnl_rate`
- `total_pnl_cny`

### 4.1 市值

```text
市值 = 当前价格 × 持仓数量
```

如果当前价格拿不到，就会回退到：

- 昨收
- 或成本价

### 4.2 原始成本总额

```text
原始成本总额 = 原始成本价 × 持仓数量
```

### 4.3 调整后成本总额

```text
调整后成本总额 = 原始成本总额 - adjustment
```

### 4.4 累计盈亏金额

```text
累计盈亏 = 市值 - 原始成本总额 + adjustment
```

也可以理解成：

```text
累计盈亏 = 市值 - 调整后成本总额
```

### 4.5 累计盈亏率

```text
累计盈亏率 = 累计盈亏 / 调整后成本总额
```

注意：

分母现在不是原始成本总额，而是：

`扣完 adjustment 之后的真实成本`

这就是为什么后来 App 的百分比从 `4.40%` 修到了 `4.69%`。

## 5. 单个持仓的当日盈亏怎么算

当前单个持仓的当日盈亏主口径，统一来自后端持仓指标：

- `day_pnl_display`
- `day_pnl_aggregate`
- `day_pnl_aggregate_cny`
- `day_pnl_rate_aggregate`

公式很直接：

```text
当日盈亏 = 当天涨跌额 × 持仓数量
```

对应到代码里就是：

```text
dailyPnl = priceInfo.change * qty
```

当日盈亏率的分母则是：

```text
昨日基准 = 昨收 × 持仓数量
```

也就是：

```text
dailyPnlPct = dailyPnl / (yclose * qty)
```

### 5.1 哪些资产不参与当日盈亏

现在后端会直接给前端标好这两类净值型基金的展示开关，前端只认结果，不自己再判断一套：

- `f_*`
- `ft_*`

因为它们很多时候白天没有新的官方净值。

当前策略相关字段是：

- `nav_update_pending`
- `day_pnl_display_enabled`
- `day_pnl_aggregate_enabled`

## 6. 分类大卡片的收益怎么算

投资页顶部汇总、分类汇总、首页投资总计，现在都应该走统一汇总层，而不是页面自己重算：

- Flutter： [portfolio_metrics_service.dart](/Users/kona/Desktop/kaka/kona_repo/flutter/lib/services/portfolio_metrics_service.dart)
- Web： [portfolioMetrics.ts](/Users/kona/Desktop/kaka/kona_repo/web/src/stores/portfolioMetrics.ts)

它们的职责不是“重新定义收益算法”，而是：

1. 优先直接吃后端给的 CNY 指标
2. 只有后端没给 CNY 字段时，才用后端同一行里的原指标乘汇率做兼容兜底
3. 不允许页面自己再从价格、昨收、成本价拼第三套算法

当前代码在：

- [invest_page.dart](/Users/kona/Desktop/kaka/kona_repo/flutter/lib/pages/invest_page.dart)

### 6.1 分类累计盈亏

每个资产先做：

```text
市值 = 当前价格 × 数量 × 汇率
成本 = 原始成本价 × 数量 × 汇率
累计盈亏 = 市值 - 成本 + adjustment × 汇率
```

然后全部相加。

### 6.2 分类累计盈亏率

分母用的是：

```text
调整后成本 = 成本 - adjustment × 汇率
```

再把所有持仓的调整后成本绝对值累加，最后算百分比。

### 6.3 分类当日盈亏

参与规则：

- 只统计允许显示当日盈亏的资产
- 基金白天待净值更新时，不参与实时当日盈亏

金额统一折成人民币显示，所以顶部明确显示 `¥`。

## 7. App 全局投资页的大数字怎么算

在 Flutter 全局状态里：

- [app_state.dart](/Users/kona/Desktop/kaka/kona_repo/flutter/lib/providers/app_state.dart)

主要有三组实时值：

### 7.1 投资总市值

```text
投资总市值 = 所有持仓的 当前价格 × 数量 × 汇率 之和
```

### 7.2 投资当日盈亏

```text
投资当日盈亏 = 所有可参与日盈亏资产的 (change × qty × 汇率) 之和
```

### 7.3 投资累计盈亏

```text
投资累计盈亏 = 所有持仓的 (市值 - 成本 + adjustment × 汇率) 之和
```

这套属于：

`实时口径`

这里的 `adjustment`，现在应理解成：

```text
总 adjustment = 旧 portfolio.adjustment + portfolio_adjustment_ledger 汇总
```

所以只要你改了持仓、价格，或者新增了分红 / 已实现盈亏 / 手工补差这类收益事件，通常会立刻变化。

## 8. 后端快照里的收益怎么算

后端快照逻辑主要在：

- [snapshot.py](/Users/kona/Desktop/kaka/kona_repo/kona_tool/core/snapshot.py)

它会对每个用户做一次统计。

### 8.1 total_pnl

后端当前公式本质上也是：

```text
浮动盈亏 = (当前价格 - 成本价) × 数量
累计盈亏 = 浮动盈亏 + adjustment
```

再乘汇率折成人民币后汇总。

也就是说：

后端快照里的 `total_pnl`，本来就包含了 adjustment。

### 8.2 day_pnl

后端快照里的 `day_pnl` 本质上是：

```text
当日浮动盈亏 = (当前价格 - 昨收) × 数量
```

如果是交易日，还会把当天已实现盈亏加进去。

但是：

- 非交易日会压成 0
- 历史日历显示时还会再按交易日口径修正

所以它不是简单“任何时刻都等于前端看到的今日盈亏”。

## 9. 分析页为什么和投资页有时对不上

这是最容易让人误会的地方。

### 9.1 投资页大多数是实时口径

比如：

- 持仓卡片
- 分类大卡片
- 当前总市值
- 当前累计盈亏
- 当前当日盈亏

它们都用：

`当前持仓 + 当前价格`

现场计算。

### 9.2 分析页要分两种

#### 实时部分

比如：

- 当日概览
- 盈亏排行

这类通常也跟当前持仓和当前价格有关。

例如：

- [app.py](/Users/kona/Desktop/kaka/kona_repo/kona_tool/app.py) 的 `/api/analysis/rank`

会直接拿当前持仓和批量价格来现算排行。

#### 历史部分

比如：

- 本月
- 本年
- 累计
- 收益日历
- 分市场日历

这类主要依赖：

- `daily_snapshots`
- `daily_snapshot_market_breakdowns`

对应代码主要在：

- [db.py](/Users/kona/Desktop/kaka/kona_repo/kona_tool/core/db.py)

所以：

你今天把持仓改对了，投资页会马上变；  
但分析页过去某个月的历史数据，不会自动跟着回写。

## 10. 月度 / 年度 / 累计收益是怎么来的

后端概览接口：

- `/api/analysis/overview`

核心逻辑在：

- [db.py](/Users/kona/Desktop/kaka/kona_repo/kona_tool/core/db.py)

它不是简单累加每天 `day_pnl`，而更接近：

`取期末 total_pnl - 取期初 total_pnl`

然后收益率优先用期初本金做分母。

这也是为什么：

- 它和“把每天前端看到的日收益加起来”

不一定完全一样。

因为后端这里更偏：

`按历史快照首尾差值来算阶段收益`

---

## 11. 你最该记住的 5 句话

1. `price` 是原始成本价，不一定等于页面显示成本价。  
2. 页面显示成本价，很多时候是把 `adjustment` 摊薄后的结果。  
3. 累计盈亏要把 `adjustment` 算进去，不然百分比会失真。  
4. 投资页大多是实时口径，分析页很多模块是历史快照口径。  
5. 改今天的持仓，不会自动改过去每天已经落库的历史收益。  

---

## 12. 当前建议

以后只要你查“这个数字为什么不对”，优先按这个顺序排：

1. 先看原始持仓里的 `price / qty / adjustment`
2. 再看当前价格和昨收
3. 再确认这是实时页面，还是历史分析页面
4. 如果是历史页，再去看对应日期快照有没有重打

这样基本就不会再把“实时数字”和“历史数字”混着看了。
