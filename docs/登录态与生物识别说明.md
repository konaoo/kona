# Auth 改造 README（账号密码 + 邀请码 + 会话持久化 + 生物识别）

本文档记录 2026-02 的认证体系改造结果，目标是让任何新会话在 5 分钟内恢复上下文并继续开发/运维。

## 1. 改造目标与结论

- 登录方式从邮箱验证码切换为 `用户名 + 密码`
- 注册方式固定为 `用户名 + 密码 + 邀请码`
- 邀请码必须前后端双校验
- 支持改密（原密码 + 新密码）
- 会话策略升级为 `365 天滑动 refresh`
- 退出登录后，若开启生物识别，可在登录页生物识别重登
- 服务端仅存最小认证状态（refresh token 哈希），不存生物特征

## 3. 核心安全策略

- 密码哈希：`scrypt`
- refresh token：服务端只存 `token_hash`，不存明文
- refresh rotation：每次 refresh 吊销旧 token，签发新 token
- 改密后：吊销该用户全部 refresh token
- 生物识别：仅调用系统 `local_auth`，人脸/指纹模板不出设备
- 审计日志：登录失败、注册、改密、refresh、logout、邀请码操作均记日志

## 4. 会话模型（客户端状态机）

客户端安全存储新增 `auth_logout_mode`：

- `normal`
- `biometric_ready`

行为规则：

1. 正常登录成功  
写入 access + refresh，清理 `auth_logout_mode`（置回 normal）。

2. 退出登录（生物识别开启）  
清 access，保留 refresh，写入 `auth_logout_mode=biometric_ready`。  
启动时不自动登录，停在登录页并展示生物识别入口。

3. 退出登录（生物识别关闭）  
清 access + refresh，写入 `auth_logout_mode=normal`。  
启动时不自动登录，需账号密码。

4. 非主动退出场景（token 过期/冷启动）  
若 `auth_logout_mode=normal` 且存在 refresh，启动时自动静默 refresh 恢复会话。

## 5. 数据库存储边界与字段释义

> 数据库：`/opt/kaka/portfolio/kona_tool/portfolio.db`

### 5.1 `users`（用户主表）

- `id`：用户ID（主键）
- `username`：用户名（唯一）
- `password_hash`：密码哈希
- `legacy_needs_password_setup`：历史账号是否需补设密码
- `password_updated_at`：最近改密时间
- `nickname`：昵称
- `avatar`：头像（URL 或 base64）
- `register_method`：注册方式（如 `password_invite`）
- `phone`：手机号（可空）
- `user_number`：用户编号
- `is_admin`：管理员标记（1/0）
- `status`：账号状态（`active`/其他）
- `created_at`：创建时间
- `last_login`：最近登录时间

### 5.2 `invite_codes`（邀请码）

- `code`：邀请码（主键）
- `batch_id`：批次号
- `status`：`active/used/revoked`
- `created_by`：创建人
- `created_at`：创建时间
- `used_by_user_id`：使用者用户ID
- `used_at`：使用时间
- `note`：备注

### 5.3 `auth_refresh_tokens`（认证最小状态）

- `id`：主键
- `user_id`：所属用户
- `token_hash`：refresh token 哈希（唯一）
- `device_id`：设备标识（可空）
- `issued_at`：签发时间
- `expires_at`：过期时间
- `revoked_at`：吊销时间（可空）
- `last_used_at`：最近使用时间（可空）

## 9. 验收命令（后端 API）

```bash
set -euo pipefail
API="http://127.0.0.1:5003"
USER="<username>"
PASS="<password>"

LOGIN_JSON="$(mktemp)"
curl -sS -X POST "$API/api/auth/login" \
  -H "Content-Type: application/json" \
  -d "{\"username\":\"$USER\",\"password\":\"$PASS\"}" > "$LOGIN_JSON"

REFRESH="$(.venv/bin/python - "$LOGIN_JSON" <<'PY'
import json,sys
d=json.load(open(sys.argv[1]))
print(d["refresh_token"])
PY
)"

curl -sS -X POST "$API/api/auth/refresh" \
  -H "Content-Type: application/json" \
  -d "{\"refresh_token\":\"$REFRESH\"}"
```

验收关注点：

- refresh 过期时间接近 365 天
- refresh 后新旧 token 不同（rotation）
- logout 后 refresh 再用应返回 401
