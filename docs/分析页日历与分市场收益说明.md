# 收益日历分市场修复与回填手册（2026-02）

本文档记录 2026-02 的收益日历问题、修复方案、数据库结构、API、回填脚本与线上验收方法。

## 1. 背景与故障时间线

### 1.1 现象

- 用户反馈分析页“收益日历历史数据缺失”。
- 排查后确认不是无记录，而是部分日期 `day_pnl` 被写成 `0` 或展示层被压成 `0`。
- 重点日期：`2026-02-16` 到 `2026-02-20`。

### 1.2 根因

1. 快照写入时刻在 `23:00 UTC`（`kona-snapshot.timer`）；
2. 原口径在“快照写入时全市场休市”场景会把日收益压零；
3. 历史数据回填场景缺少逐日交易证据时，分市场拆分存在不确定性。

### 1.3 修复结果

- 修复日收益口径，交易日不再因“写入时段休市”被错误压零；
- 新增分市场日收益存储与查询；
- 新增回填脚本（总收益修复 + 分市场修复）；
- 对“无证据历史日”采用 `unallocated` 承载，不伪造市场归因。

## 2. 数据结构与接口

## 2.1 新增表：`daily_snapshot_market_breakdowns`

- 主键：`id`
- 唯一键：`UNIQUE(date, user_id, market)`
- 字段：
  - `date TEXT NOT NULL`
  - `user_id TEXT NOT NULL DEFAULT ''`
  - `market TEXT NOT NULL`（`a|hk|us|fund|unallocated`）
  - `day_pnl REAL NOT NULL`
  - `source TEXT NOT NULL`（`exact|estimated`）
  - `confidence REAL NOT NULL DEFAULT 1.0`
  - `meta_json TEXT`
  - `updated_at TIMESTAMP`
- 索引：
  - `(user_id, date)`
  - `(date)`
  - `(source)`

## 2.2 新增接口：`GET /api/analysis/calendar/market_breakdown`

- 参数：
  - `time_type` 或 `type`：目前仅支持 `day`
  - `year`
  - `month`
- 返回：
  - `items[].date`
  - `items[].markets.{a,hk,us,fund,unallocated}`
  - `items[].total_pnl`
  - `items[].source`（`exact|estimated|missing`）

示例：

```json
{
  "time_type": "day",
  "year": 2026,
  "month": 2,
  "items": [
    {
      "date": "2026-02-17",
      "markets": {
        "a": 0.0,
        "hk": 0.0,
        "us": 0.0,
        "fund": 0.0,
        "unallocated": 5849.3
      },
      "total_pnl": 5849.3,
      "source": "estimated"
    }
  ]
}
```

## 5. `estimated` 与 `unallocated` 解释

- `exact`：来自快照当时的分市场精确计算。
- `estimated`：历史回填估算结果，不代表逐笔成交级精确归因。
- `unallocated`：无法可靠分配到 A/HK/US/Fund 的部分。

### 5.1 为什么“美股为 0”会出现

若某历史区间内没有可重放的美股交易与持仓证据，估算链路不会凭空造出美股收益，结果可能是：

- `us = 0`
- 日收益主要进入 `unallocated`。

先查证据再解释收益归因：

```bash
cd /opt/kaka/portfolio/kona_tool
export DB_PATH="/opt/kaka/portfolio/kona_tool/portfolio.db"
export KONA_USER_ID="<user_id>"

JWT_SECRET=tmp .venv/bin/python - <<'PY'
import os, sqlite3
db = os.environ["DB_PATH"]
uid = os.environ["KONA_USER_ID"]
conn = sqlite3.connect(db); conn.row_factory = sqlite3.Row
cur = conn.cursor()
rows = cur.execute("""
SELECT id, time, code, type, qty, price, pnl
FROM transactions
WHERE COALESCE(user_id,'')=? AND substr(time,1,10) <= '2026-02-20'
ORDER BY time ASC, id ASC
""",(uid,)).fetchall()
print("tx_count<=2026-02-20:", len(rows))
for r in rows[:30]:
    print(r["time"], r["code"], r["type"], r["qty"], r["price"], r["pnl"])
conn.close()
```

## 7. 风险与已知限制

1. 历史估算精度不可逆：缺少历史交易或仓位快照时，只能“尽力估算”。
2. `exchange_calendars` 覆盖范围不足会产生告警日志（如仅到 2025-12-31）。
3. `estimated` 不应作为审计级别归因依据，建议 UI 明示数据来源。
4. 若需精确历史分市场归因，必须保留完整逐日仓位快照或逐笔成交可回放链路。

## 9. 与 Flutter 刷新口径的衔接（2026-02-22）

本手册侧重后端与 DB。若要完整理解“用户在 App 上看到什么”，需结合 Flutter 最新口径：

1. 休市时显示冻结的最近有效日涨跌，不再统一压零。
2. 行情失败回退链：
   - 实时价 -> 上次缓存价 -> 收盘快照价 -> 成本价。
3. 首页投资资产按价格口径重算，不再固定成本口径。
4. 首页不再展示“资产更新时间/行情更新时间/离线缓存”文案。
