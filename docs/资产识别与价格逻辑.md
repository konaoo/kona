# 资产识别与价格逻辑

## 1. 这份文档是干什么的

这份文档专门讲一件事：

`系统是怎么识别一只资产，并决定去哪里拿价格的。`

你可以把它理解成一条完整链路：

1. 用户输入一个代码
2. 系统先把代码标准化
3. 再判断它属于 A 股、港股、美股还是基金
4. 再判断它默认应该是什么币种
5. 最后按资产类型去不同的数据源取价格

这份文档就是把这 5 步讲清楚。

---

## 2. 先看总原则

系统内部最核心的资产分类只有 4 类：

- `a` = A股
- `hk` = 港股
- `us` = 美股
- `fund` = 基金

你现在只要先记住这张最粗的表：

| 输入或前缀 | 系统归类 |
| --- | --- |
| `sh / sz / bj` | A股 |
| `hk / .HK / 5位数字` | 港股 |
| `gb_ / 纯字母` | 美股 |
| `f_纯数字 / ft_` | 基金 |
| `f_字母` | 纠偏成美股 |

## 3. 第一步：代码怎么标准化

这一步代码在：

- [parser.py](/Users/kona/Desktop/kaka/kona_repo/kona_tool/core/parser.py)

作用很简单：

`把用户输入的各种写法，统一改成系统内部认得的格式。`

### 3.1 纯数字输入

#### 5 位纯数字

默认按港股处理。

例如：

- `00700 -> 00700.HK`

默认币种：

- `HKD`

#### 11 开头的 6 位数字

默认按基金处理。

例如：

- `110018 -> f_110018`

#### 16 开头的 6 位数字

也按基金处理。

例如：

- `161907 -> f_161907`

#### 6 / 5 / 9 开头的 6 位数字

按沪市处理。

例如：

- `600000 -> sh600000`
- `511360 -> sh511360`
- `900901 -> sh900901`

#### 0 / 3 / 1 / 2 开头的 6 位数字

按深市处理。

例如：

- `000001 -> sz000001`
- `159655 -> sz159655`
- `200002 -> sz200002`

#### 4 / 8 开头的 6 位数字

按北交所处理。

例如：

- `830001 -> bj830001`

### 3.2 港股格式

如果输入本来就带 `.HK`，那按港股处理。

例如：

- `00700.HK`

### 3.3 纯字母

纯字母默认按美股处理。

例如：

- `AAPL -> gb_aapl`

## 4. 第二步：系统怎么判断市场分类

这一步代码在：

- [asset_type.py](/Users/kona/Desktop/kaka/kona_repo/kona_tool/core/asset_type.py)

真正页面里看到的分类，是下面 4 类：

- A股
- 港股
- 美股
- 基金

### 4.1 A股

这些都会被归到 A股：

- `sh...`
- `sz...`
- `bj...`

也就是说：

- 普通 A 股股票算 A股
- 场内 ETF 只要是 `sh/sz` 开头，也算 A股
- 北交所也暂时放在 A股

一句话：

`只要是 sh / sz / bj 开头，系统就归到 A股。`

### 4.2 港股

这些会被归到港股：

- `hk...`
- `xxxx.HK`
- 5 位纯数字

例如：

- `hk00700`
- `00700.HK`
- `00700`

一句话：

`5位数字或 hk / .HK，都按港股。`

### 4.3 美股

这些会被归到美股：

- `gb_...`
- 纯字母代码
- 被误写成 `f_` 但后面其实是字母的代码

例如：

- `gb_aapl`
- `AAPL`
- `f_NUGT`

这里有个很重要的纠偏规则：

`f_` 不等于一定是基金。`

只有 `f_` 后面是纯数字，才算基金。

如果是：

- `f_NUGT`
- `f_BOXX`

这种字母型 `f_`，系统会认为这是误标，最后按美股处理。

### 4.4 基金

这些会被归到基金：

- `f_` 开头并且后面是纯数字
- `ft_...`

例如：

- `f_110018`
- `f_161907`
- `ft_LU1116320737`

一句话：

`f_纯数字 和 ft_ 都算基金。`

## 5. 第三步：系统怎么判断默认币种

币种规则主要在：

- [parser.py](/Users/kona/Desktop/kaka/kona_repo/kona_tool/core/parser.py#L11)

注意：

`市场分类` 和 `币种` 不是一回事。

但系统会根据代码强制给一些币种规则。

### 5.1 强制币种规则

- `sh900xxx` -> `USD`
- `sz200xxx` -> `HKD`
- `gb_...` -> `USD`
- `ft_...` -> `USD`
- `hk...` 或 `.HK` -> `HKD`
- `sh / sz / bj / f_` -> `CNY`

### 5.2 重点理解

这里最容易搞混的是 B 股：

- 沪 B：`sh900xxx`，虽然也是 `sh`，但币种不是人民币，是 `USD`
- 深 B：`sz200xxx`，虽然也是 `sz`，但币种不是人民币，是 `HKD`

所以系统对 B 股有专门优先规则，不让它们被普通 `sh/sz` 逻辑覆盖掉。

## 7. 特殊情况

### 7.1 场内 ETF 被错存成 `f_`

有些资产虽然代码写成了 `f_`，但本质上是场内交易基金。

例如：

- `511360`

这类情况，系统会先尝试把它纠正成交易所代码，比如：

- `sh511360`

如果能拿到场内价格，就优先走场内价格，不继续走场外基金净值。

对应代码：

- [_exchange_fund_candidates](/Users/kona/Desktop/kaka/kona_repo/kona_tool/core/price.py#L172)
- [_map_fund_code_to_exchange_if_tradable](/Users/kona/Desktop/kaka/kona_repo/kona_tool/core/price.py#L188)

一句话：

`看起来像场内 ETF 的 f_ 基金，系统会尽量纠正回场内价格。`

### 7.2 `968xxx` 为什么特殊

因为这类海外基金经常出现：

- 天天基金慢半拍
- 腾讯 `jj` 口径不稳
- 东财 F10 不一定总能给到

所以现在规则是：

- 东财确认净值优先
- 东财拿不到时，`968xxx` 优先走 overseas 海外基金页

目的是尽量避免拿到旧值。

### 7.3 `ft_` 为什么和普通 `f_` 不一样

因为 `ft_` 这类基金更依赖：

- 基金公司官方页
- 海外财经站点

所以系统不会把 `ft_` 和普通 `f_` 放在一套基金逻辑里处理。

## 9. 当前结论

你只要先记住这几句就够了：

1. `sh / sz / bj` 都按 A股处理。
2. `hk / .HK / 5位数字` 都按港股处理。
3. `gb_` 和纯字母代码按美股处理。
4. `f_` 只有后面是纯数字时才真的是基金。
5. `ft_` 是特殊基金，优先看官方。
6. 普通基金优先看确认净值，不优先信估算值。
