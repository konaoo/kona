## 5. 已踩坑与修复

### 5.1 登录返回 500

现象：
- `POST /api/auth/login` 返回 `500`

根因：
- `.env` 使用 `RATELIMIT_STORAGE_URL=redis://127.0.0.1:6379/0`
- 迁移后 Redis 未安装，Flask-Limiter 连接失败

修复：
- 安装并启用 Redis
- 保持 `.env` 为 `RATELIMIT_STORAGE_URL=redis://127.0.0.1:6379/0`

### 5.2 迁移后入口服务混乱（Nginx/Caddy）

现象：
- 访问结果不稳定，可能出现默认页、TLS 异常或握手重置

根因：
- 入口服务切换阶段配置不一致（Nginx/Caddy 并存或证书链路不一致）

修复方向：
- 固定单一入口（当前为 Caddy）
- 保持 `:5003` 仅本机监听
- 每次改动后跑 HTTPS 冒烟

## 6. 安全与端口策略

- 对外仅开放：`22`（SSH）、`80`（HTTP）、`443`（HTTPS）
- `5003` 仅本机监听，不对公网开放
- 防火墙中不应长期保留 `5003` 公网入站规则

## 8. 回滚预案（最小）

如果新机出现不可恢复故障：

1. 临时恢复旧 AWS 入口（若旧机仍保留且服务可启动）
2. 把客户端基地址切回旧入口并重新发包
3. 排障完成后再切回腾讯云

注意：
- 停 AWS 前需确认无新写入，避免新旧库分叉

## 10. 停 AWS 前最终同步清单（强烈建议）

1. 先冻结旧 AWS 写入窗口（公告维护，避免新旧双写）。
2. 在旧 AWS 导出最新数据库备份。
3. 将备份拷贝到腾讯云并覆盖到目标路径：
   - `/opt/kaka/portfolio/kona_tool/portfolio.db`
4. 重启腾讯云业务服务并做冒烟：
   - 登录、资产列表、添加资产、管理后台用户页
5. 确认新服务器日志无异常后，再停 AWS。
6. 停机后观察 24-48 小时，无异常再做旧机资源清理。
